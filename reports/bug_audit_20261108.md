# Lumen 全量 Bug 审计报告（2026-11-08）

对 `Lumen/` 全部 Python 代码（约 1.4 万行，36 个模块）做了系统化审计：两个子代理分片通读 `core/` 与 `tools/guard/installer/main/boot-anim`，并交叉 grep 高危模式（裸 except、TODO/FIXME、全局可变状态）。语法检查 `py_compile` 全绿。

## 一、本次修复的 Bug（15 处，均已改 + 语法校验通过）

### 致命
1. **tools/fetch_gptoss.py** — 权重下载完整性校验**永远失败**：第 191 行用固定 `chunk_size` 累加 `written["n"]`，而 `total`(11624759488) 不被 64MB 整除 → `got != total` 恒成立 → 任何情况下退出码都是 1（脚本事实不可用）；且第 159 行只看 `getsize==EXPECTED_SIZE` 跳过，会把上次失败留下的**全零稀疏文件误判为完整交付**。
   → 改真实字节累加 `(end-start+1)`；成功下载后写 `.done` 标记，skip 判断叠加 `.done` 校验。

### 高
2. **core/weights.py** — 取消的下载被标「已完成」：`_download` 并行分支与 `_worker` 在用户点取消后都无条件写 `done`，覆盖掉取消状态 → UI 状态错乱。
   → 两处在写 `done` 前加 `_task["cancel"]` 检查，取消时直接返回（内部已写 `cancelled`）。
3. **guard/lumen_guard.py** — 看门狗**重启风暴 + 孤儿进程**：旧 Lumen 僵死占着 8770 时，新进程绑定失败反复拉起；且不杀旧进程、不回收子进程（llama-server）。
   → `start_lumen` 启动前清理 `runtime.json` 中记录的**自身旧 pid**（TerminateProcess），严格不触碰其它进程。
4. **tools/vs_build.py** — 被测程序运行超时，`subprocess.run` 抛 `TimeoutExpired` 时 `rr` 未绑定 → 下一行 `NameError` 崩溃（且被上层误报成「编译异常」掩盖真实超时）。
   → 包裹 `try/except subprocess.TimeoutExpired`。

### 中
5. **main.py** — `write_runtime` 未重置 `clean_exit`：上次正常关窗残留的 `clean_exit=True` 会让新实例崩溃后守护失效。
   → 写入时显式 `"clean_exit": False`。
6. **tools/regression_eval.py** — 主路径 `json.load(f).get("summary") or json.load(f)` 第二个 load 从 EOF 读 → `JSONDecodeError` 崩溃。
   → 单次 `json.load` 后取 summary。
7. **core/engine.py** — 发给 llama-server 的 `model` 恒为 `"local"`，多模型/严格匹配后端会 400。
   → 改为 `kw.get("model") or lc.get("model") or "local"`（用真实模型名）。
8. **core/server.py** — 静态资源 `_serve_asset` 未归一化反斜杠，`%5c` 在 Windows 下可能路径穿越；同会话并发 `/api/chat` 会互相覆盖 Runner。
   → 反斜杠先 `replace("\\","/")` 再 normpath；同 `sid` 已有进行中请求时返回 409。
9. **tools/tunnel_keeper.py** — 拿不到隧道 URL 时 ssh 进程泄漏（脱管）。
   → `start()` 在未拿到 URL 且 proc 存活时主动 `terminate()`。

### 低（顺手修）
10. **core/knowledge.py** — `relevant()` off-by-one 仍未彻底修（实际多返回 1 条）→ 改 `if i > k`；`_absorb_feeds` 的 `one()` 异常分支引用未绑定 `etag/last_mod` → 循环前初始化。
11. **core/remote.py** — `handle_command` 直接改 `gate.session` 未走 `gate.lock` → 用 `with gate.lock` 包住。
12. **core/firewall.py** — `_all_rules` 冗余的 `for enc in (utf-8,gbk)` 重跑 netsh 两次（`enc` 未使用）→ 删除冗余循环。
13. **core/agent.py** — 工具循环 `while step <= max_steps` 实际多跑一轮（step 先 +=1）→ 改 `while step < max_steps`。
14. **tools/h1_one.py** — `ran = stdout = False, ""` 元组赋值笔误 → `ran, stdout = False, ""`。
15. **tools/e2e_remote.py** — 只捕获 `HTTPError`，服务器未起时 `URLError` 未捕获致测试脚本崩 → 补 `URLError`。

## 三、标注未动（需用户确认或高风险，本批未改）
- **llamacpp.ensure 启动锁**：锁内 `_wait_ready` 最长阻塞 110s，期间 `stop()`/并发 `ensure` 被阻塞。改锁粒度有并发风险，需确认后动。
- **build_release.verify_payload fail-closed**：当前 `except Exception: return True` 吞校验异常。改为 fail-closed 可能误伤正常构建，需加 `--strict/--lenient` 开关。
- **installer 代理/完整性**：`_http_get` 用 `ProxyHandler({})` 强制禁用代理（国内走代理用户 APK/GitHub 资产必败）；跳过已存在文件不校验完整性（可能接受半截文件）。installer 改动风险中等。
- **screencap_service jpeg 文案**恒为 True：本想改 `jpegenc.available()`，但该模块未导入 `jpegenc`，改了会 `NameError`；仅影响 UI 文案，无功能影响，暂不动。
- **e2e_identity 连接保护**：测试桩无 except 结构，连接被拒会崩；改动较大，标注。
- **onnx_engine 并发/停止透传**：非主路径（默认走 llamacpp），未动。
